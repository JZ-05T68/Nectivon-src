# Nectivon v0.8.6

[简体中文](README.md) | [English](README_EN.md) | **日本語**

**Nectivon**（旧称：Engineering Knowledge Base / EKB）は、長期的な個人の知識資産を蓄積・整理・検証し、
必要なときに再利用するための、ローカルファーストな個人知識・経験システムです。

## プロダクトの位置づけ

Nectivon は工学知識の管理から始まりましたが、単なる PDF 質疑応答ツール、RAG ユーティリティ、
文書検索エンジンではありません。資料管理から個人知識・経験システムへと発展し、ユーザー自身の
知識、経験、失敗、方法、判断、プロジェクト履歴、意思決定、修正、結果を蓄積し、再び活用できる
ようにすることを目指しています。

汎用 AI が「世界の知識」を呼び出すことを得意とする一方、Nectivon はユーザーが「過去に蓄積した自分」
を呼び出せるようにすることを目指します。すべての資料はユーザーが明示的に取り込むか許可したもの
に限られ、ローカルファイルと SQLite データベースが引き続き事実のソースです。AI は任意の拡張層です。

```text
資料 → 理解 → 知識オブジェクト → 出典検証 → 個人経験 → 検索・想起 → 再利用 → 工学的能力
```

## 主な機能

- PDF を取り込み、SHA-256 で重複を検出し、ページ単位で描画して既存のテキスト層を抽出します。
- スキャンページ、画像、グラフなどの視覚的ページをページ単位で読み取り、最終的な根拠は実際の文書ページへ戻して提示します。
- SQLite FTS5、フィールド重み付け、希少項目の補助検索、任意のハイブリッド検索で資料を検索します。
- 知識オブジェクト、出典、証拠、改訂、関係、個人メモリを整理します。
- 資料、保存済みの生 Q&A、正式な経験を区別し、出典、権威レベル、ユーザー確認状態を保持します。
- Agent が読み取り専用ツールを選択し、資料を読み、証拠を取得して、引用に制約された回答を生成します。
- バージョン系列、旧値、置き換え済みの値、対象の帰属、デバイス間・モデル間のパラメータ混同を防ぎます。
- 完全なローカルバックアップを作成・検証・復元し、連続したマイグレーション、整合性チェック、
  外部キー検査によってデータベースを保護します。

### v0.8.4 — 過去の開発と限定的な信頼性テスト（差し戻し済み）

当時の v0.8.4 の作業では、v0.8.x の焦点を「Agent がツールを呼べるか」から、
現実的で口語的、不完全、かつ混同しやすい依頼に対して、正しい情報を安全に見つけ、対応付け、
根拠を説明できるかへと進めました。現在のバックエンド信頼性ベースラインは凍結済みです。

主な内容：

- 口語表現、中国語数字、1 文字の手掛かり、専門用語との差異に対する検索強化。
- 「前に」「この前」などの時間表現によって、ページ位置を尋ねる質問が誤った知識ソースへルーティングされないための規律。
- バージョン、条件、対象、デバイス間パラメータの取り違えを防ぐ継続的な保護。
- 視覚情報、テキスト、Saved QA、個人経験の出典・権威境界。
- 古い、誤っている、または権威の低い証拠を明示的に拒否または状態表示する仕組み。
- 現在の検索証拠が不足している場合に、局所的な検索失敗を「知識ベース全体に存在しない」と拡大せず、
  範囲を限定して正直に不足を伝える応答。
- 最終の独立シミュレーション・ユーザー再テストを実施し、既知の P0、P1、blocking P2 がない状態で
  バックエンド信頼性ベースラインを凍結。
- 凍結済みバックエンドを code-only で 8501 Competition Stable に昇格し、正式データを保持したまま
  8511 staging を分離。

v0.8.4 のバックエンド信頼性は凍結されていますが、これは検索再現率が 100% であることや、
製品が決して失敗しないことを意味しません。少量の Honest Omission（安全な取りこぼし）は残っています。
関連資料が存在していても、その問い合わせでは取得できない場合があり、そのときシステムは無関係な内容で
埋めるのではなく「現在の証拠では不足している」と明示します。この過去の結果は v0.8.6 の公開審査や実ユーザー受入れ検証の代わりにはなりません。

## 過去の v0.8.4 信頼性証拠（現在のリリース結論ではない）

v0.8.4 の最終独立シミュレーション・ユーザー再テストは、開発担当とは別のテスター役が、
凍結された同一バックエンドコードを対象に実施しました。233 回の同一パイプライン Agent 実行を記録し、
その証拠セットでは、誤った具体的回答（Commission）、捏造（Fabrication）、バージョン・条件・対象の
対応付けエラー、証拠の権威エラー、根拠のない知識ベース全体への否定断言は観測されませんでした。
過去の 9 件の重点残留ケースは、7 件の直接 PASS、2 件の正直な境界応答、0 件の信頼性失敗でした。

一方で、232 件の一意なケースのうち 32 件は Honest Omission でした。対象資料は存在するものの検索に
成功せず、システムは範囲を限定して「現在の証拠では不足」と応答しました。これは検索の recall に
改善余地があることを示すものであり、100% recall や「失敗しない」と説明すべきものではありません。

凍結時の状態：

- `OPEN P0 = 0`
- `OPEN P1 = 0`
- `OPEN BLOCKING P2 = 0`
- `M1R-A = RESOLVED_WITH_HONEST_OMISSION_MONITOR`
- `M1R-B = RESOLVED_MONITOR`
- `M2 = RESOLVED_MONITOR`
- `M3 = ARCHITECTURE_REQUIRED_UNCHANGED`

M3 は、完全な conversation history が現在の凍結済み機能ではないことを示します。複数ターンにまたがる
曖昧な指示に十分な文脈がない場合、安全のため確認を求めることが現在のプロダクト境界です。

元の内部テスト記録は公開候補の作業ツリー外に保管しています。確認が必要な場合はメンテナーに内部アーカイブの閲覧を依頼してください。

## ローカル実行と安全性

要件：Windows 10/11、PowerShell、Python 3.11、FTS5 を利用できる Python SQLite ビルド。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -m streamlit run app.py
```

正式サービスは `127.0.0.1:8501` にバインドされます。`data/`、`backups/`、`logs/`、`runtime/`、`.env`、
データベース、ユーザー資料、ページ画像は Git に入れてはいけません。本プロジェクトには登録、ログイン、
アカウント、マルチユーザー権限、クラウド同期はありません。API Key がなくてもオフラインのコア機能は利用できます。
