# v0.8.7：跨星云的知识点直接连线

需求：当不同学科星云中的两个知识点已有明确关系时，连接具体的知识点。

## 数据与显示

现有 SQLite `knowledge_relations` 已能保存两个知识对象之间的关系，包括起点、终点、
类型和说明。本次直接复用该表，数据库 schema 保持 v37，不需要再迁移，也不批量推断或写入新关系。
既有关系会自动用于星图，人工确认新关系仍通过原有“添加知识点之间的关系”保存。

原星图已经保留点到点关系，但跨星云线较淡，且多学科对象若分配到同一主星云，会被画成内部关系。
本次在星图投影中标记明确涉及多个一级学科的知识点关系；分类和原始关系行保持原样。
渲染器保留关系方向、类型标签、说明，明确的跨学科关系以更清楚的桥接线显示。
单学科关系、知识点到星云的归属线、来源线的原有显示保持；空星云继续隐藏。
隐藏或搜索过滤掉端点时不生成悬空连线，不因为两个学科有关联而假定所有知识点相互关联。

原有关系编辑器显示候选知识点所属学科，便于选择跨星云的具体起点与终点。
可选 AI 归纳沿用原有单次调用，明确要求保留原文支持的跨学科知识点关系；
仍需用户核对并确认保存，没有新增付费识别调用或自动分析已有知识库。

## 修改文件

- `src/knowledge_graph_service.py`：星图投影识别跨学科关系，保留原始关系和节点。
- `scripts/build_starmap_component.py`、生成的 `src/components/knowledge_starmap/index.html`：
  适配器保留关系字段，识别多学科关系并提高其连线可见度；上游源码不变。
- `src/knowledge_graph_ui.py`：原有关系编辑器显示学科标签。
- `src/knowledge_mining_service.py`：原有归纳提示词明确覆盖有原文依据的跨学科关系。
- `tests/test_knowledge_graph.py`、`tests/test_knowledge_mining.py`、
  `tests/js/knowledge_starmap.test.cjs`：持久化、UI 确认、AI 草稿、投影与渲染回归。
- `README.md`、`README_EN.md`、`README_JP.md`：同步说明。
