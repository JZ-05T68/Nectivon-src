# v0.8.7：同一个知识点关联多个星云

本次是本地维护修改：一个知识对象可以保存多个学科归属，并同时连接各个学科星云。
同一个知识点只保存一份原文、来源和内容修订历史；多个二级方向属于同一学科时不会重复连线。
空星云继续隐藏，不恢复此前移除的“展开一级星云”页面控件。

## 保存与展示

- 知识点详情提供折叠的“关联更多学科”，用户多选并点击“保存学科关联”后才追加分类。
  已有分类和二级方向保持，重复保存不重复增加，不改变内容确认和修订状态。
- 可选 AI 资料归纳沿用现有单次调用：原文明确涉及多个学科时，在同一个草稿知识点中列出多个分类。
  旧版单学科草稿仍可读取；用户核对草稿并确认后保存。没有新增学科识别调用。
- 星图快照合并全部保存分类，来源页和来源文档继承这些分类，沿用现有跨星云连线。
  共享节点计入每个相连星云的节点数量。

## 数据兼容

SQLite schema v36 → v37 仅调整 `knowledge_subject_classifications` 的主键：
由单一 `knowledge_object_id` 改为 `(knowledge_object_id, subject, subdiscipline)`。
升级前沿用既有 SQLite 在线备份和完整性检查；转换在一个事务中保留所有旧分类，失败回滚。
本次不改写知识原文、PDF、页面图片或用户笔记。

已有 v36 只读 Hosted 示例库的列结构兼容。它经过既有完整校验后保持 v36，
只初始化运行时 WAL，不升级输入示例库；本地可写知识库默认照常执行升级。
没有扩展 Hosted 写入功能。

结果：Ruff 通过；三组 pytest 分别 179、203、58 项通过（合计 440）；JavaScript 3 项通过。
测试涵盖单对象多分类、追加保存、重复保存、非法输入、来源继承、旧分类备份升级、迁移失败回滚、
页面确认、旧示例库启动与再次启动、数据库和备份，以及原有外语第一层与语音输入兼容回归。

限制：本轮未执行全量 pytest，也没有调用真实 AI。已有 Starlette/httpx 弃用提示仍存在，
与本次变更无关。AI 分类仍需用户对照资料核对；已有知识点不会自动追加未经确认的分类。
本次本地修改没有推送 GitHub，也没有创建 Release。
