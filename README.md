# Nectivon v0.8.6

**简体中文** | [English](README_EN.md) | [日本語](README_JP.md)

**Nectivon**（曾用名：Engineering Knowledge Base / EKB）是一个本地优先的个人知识与经验系统，用于长期沉淀、
组织、验证和重新调用个人知识资产。

## v0.8.6 使用

Windows 10/11 与 Python 3.11+ 环境下，先运行 `check_environment.bat`。如提示缺少依赖，执行：

```powershell
python -m pip install -r requirements\requirements.txt
```

启动脚本固定绑定回环地址，不向局域网开放：

- `启动正式版.bat` / `stop_release.bat`：正式实例 `127.0.0.1:8501`；
- `run_all_tests.bat`：依次执行 Ruff 和全部 pytest 回归测试。

8511/8512 是内部隔离测试环境，不包含在公开发行包的启动脚本中。

### 五个 AI Provider 的配置位置

v0.8.6 支持 Qwen、DeepSeek、Kimi、Hunyuan、GLM。请在 Web 界面
`系统设置 → AI / 模型服务` 中选择 Provider、模型并保存 API Key；不需要直接编辑 JSON。

- 非敏感 Provider 设置：`%LOCALAPPDATA%\Nectivon\config\ai-providers-v1.json`；
- API Key：优先保存在 Windows 凭据管理器，DPAPI 加密回退文件位于
  `%LOCALAPPDATA%\Nectivon\credentials\ai-v1.bin`；
- 8511/8512 的设置与凭据分别保存在对应测试数据根下，不会读取或覆盖正式配置；
- `.env` 中的 `EKB_AI_API_KEY` 只保留为旧版 Qwen 兼容入口。其余四个 Provider 不使用明文环境变量保存 Key。

未配置任何 API Key 时应用仍可启动，全部本地知识管理和针对训练功能保持可用。

## 产品定位

Nectivon 以工程知识库为最初应用领域，但它不只是 PDF 问答工具、RAG 工具或文档搜索器。它正在
从资料管理走向个人知识与经验系统：帮助用户积累并重新调用自己的知识、经验、错误、方法、
判断、项目历史、决策、修正和结果。

通用 AI 更擅长调用世界的知识；Nectivon 希望帮助用户调用过去积累的自己。所有资料仍由用户主动
导入或明确授权，本地文件和 SQLite 数据库仍是事实来源，AI 只是可选增强层。

```text
资料 → 理解 → 知识对象 → 来源核验 → 个人经验 → 检索与召回 → 复用 → 工程能力
```

## 核心能力

- 导入 PDF，使用 SHA-256 检测重复文件，逐页渲染并提取文本层；
- 对扫描页、图片、图表和视觉型页面进行页面级读取，并回到真实文档页作为最终证据；
- 使用 SQLite FTS5、字段权重、特异性补充召回和可选混合检索查找资料；
- 组织知识对象、来源、证据、修订、关系和个人记忆；
- 区分资料、原始问答与正式经验，保留来源、权威等级和用户确认状态；
- 让智能体选择只读工具、读取资料、获得证据，并生成受引用约束的回答；
- 对版本族、旧值、已被取代数值、对象归属及跨设备/跨型号参数实施可靠性保护；
- 创建、验证和恢复本地完整备份，并通过连续迁移、完整性和外键检查保护数据库。

## 当前版本

当前源码版本为 v0.8.6；正式发布标识见本仓库的 v0.8.6 Tag 与 Release。8511 是内部测试服。
v0.8.4 因后续发现较多问题而被打回，**不是当前正式发布版本**。以下 v0.8.4 内容仅记录当时的开发与限定测试结论。
公开发行包不含未确认再分发依据的学校、专业与目录来源 JSON。缺少这些数据时，高等教育目录查询与新增配置明确提示不可用；已有资料保留，基础教育配置、导入、检索、学习整理、讲题和本地训练仍可运行。目录相关回归测试需要另行提供有授权的数据。

### v0.8.4 — 历史开发与限定可靠性测试（已打回）

当时的 v0.8.4 工作把 v0.8.x 的重点从“能否调用工具”进一步推进到“能否在真实、口语化、
不完整和容易混淆的请求中安全地找对、用对并说明证据”，并完成了当前后端可靠性基线的冻结。

主要内容包括：

- 面向自然口语、中文数字、单字线索和专业词差异的检索加固；
- 定位类问题的工具路由纪律，避免被“上次”“之前”等时间词误导到错误知识来源；
- 对版本、条件、对象和跨设备参数的持续约束，避免“找到了资料却用错资料”；
- 视觉内容、文本内容、Saved QA 与个人经验之间的来源和权威边界；
- 对过时、错误或不可靠证据的显式降权、拒用和状态披露；
- 当当前检索证据不足时采用限定范围的诚实说明，不把局部检索失败扩张成“整个知识库没有”；
- 完成最终独立模拟用户复测，并在无已知 P0、P1 或 blocking P2 的条件下冻结后端可靠性基线；
- 以 code-only 方式将冻结后端提升到 8501 Competition Stable，同时保留正式数据并保持 8511 staging 隔离。

v0.8.4 的后端可靠性已经冻结，但这不代表产品永远不会出错，也不代表召回率达到 100%。当前仍存在少量
安全遗漏（Honest Omission）：资料可能存在但本次没有成功召回，此时系统应明确说明当前证据不足，而不是
使用无关内容补答案。这些历史结果不能替代 v0.8.6 的发布审计或真人使用验收。

## 历史 v0.8.4 可靠性证据（非当前发布结论）

v0.8.4 的最终独立模拟用户复测由独立测试角色完成，测试对象与冻结后端代码一致。该轮共记录 233 次同管线
Agent 执行；在这组证据中，未观察到错误具体答案（Commission）、伪造内容（Fabrication）、版本/条件/对象
绑定错误、证据权威错误或全库范围的错误否定断言。历史 9 个重点残留案例最终表现为 7 个直接通过、2 个
诚实边界、0 个可靠性失败。

同时，32/232 个唯一用例属于 Honest Omission：目标资料存在但没有被成功召回，系统以限定范围的“当前证据
不足”回应。该指标说明检索召回仍有优化空间，但与错误回答不同，不应被描述为“100%召回”或“绝对不会出错”。

当前冻结结论：

- `OPEN P0 = 0`
- `OPEN P1 = 0`
- `OPEN BLOCKING P2 = 0`
- `M1R-A = RESOLVED_WITH_HONEST_OMISSION_MONITOR`
- `M1R-B = RESOLVED_MONITOR`
- `M2 = RESOLVED_MONITOR`
- `M3 = ARCHITECTURE_REQUIRED_UNCHANGED`

M3 仍表示完整 conversation history 尚未作为当前能力冻结；在缺少必要上下文的跨轮裸指代中，安全澄清仍是
当前产品边界。

上述内部测试原始记录已从公开候选工作树移出并保存在仓库外部；若需复核，应向维护者申请查看内部归档。

## 本地运行与安全

要求：Windows 10/11、PowerShell、Python 3.11，以及支持 FTS5 的 Python SQLite。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -m streamlit run app.py
```

正式服务固定绑定 `127.0.0.1:8501`。`data/`、`backups/`、`logs/`、`runtime/`、`.env`、
数据库、用户资料和页面图像都不应进入 Git。项目不包含注册、登录、账号、多用户权限或云同步；
没有 API Key 时离线核心功能仍可用。
